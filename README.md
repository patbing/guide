# GUIDE — 보행 안내 스파이크

출구에서 목적지 입구까지, **실시간 위치 + 180° 판정 + 말로 하는 랜드마크 대화**를 검증하는 1주 스파이크입니다.

- **채팅 우선**: "근처 카페 추천" → 후보 카드 → 선택 → 경로 미리보기 → 길안내
- 파일럿 경로: **잠원역 4번 출구 → 르 파운드** (667m, 회전 4회, 골목 포함)
- 데모 POI: 잠원 주변 OSM 카페/식당 8곳 (평점·영업시간은 카카오 키 연결 후)
- PWA, 프레임워크 없음(바닐라 ES 모듈), GitHub Pages
- 1차 채팅은 **규칙 기반 파서**입니다. LLM 도구 호출은 다음 단계에서 붙입니다.

## 실행

```powershell
cd guide
python -m http.server 8792 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8792/` (HTTPS 또는 localhost에서만 GPS/나침반 동작)

## 테스트

```powershell
cd guide
node --test
```

E2E (서버가 8792에서 실행 중이어야 함):

```powershell
python test/e2e/guide_e2e.py
python test/e2e/chat_e2e.py
python test/e2e/flag_e2e.py
```

채팅 E2E는 `?demo=1`로 잠원역 기준 후보를 띄우고, 카드 선택 → 경로 미리보기까지 검증합니다.
가이드 E2E는 `window.__guide` 디버그 API로 GPS/나침반을 모킹해
출구→방향 확정→안내→이탈→복귀→랜드마크 답변→도착→역방향을 검증합니다.
깃발 E2E는 **음성 기본 0회**, 음성 ON일 때 회전만 발화, 진동 패턴, 작은 걸음 course,
이탈/복귀, 입구 1회/2회 확인을 검증합니다.

## 현재 동작

0. **채팅(첫 화면)**: "근처 카페 추천" → 위치 기준 후보 3곳 카드 → 선택.
   - `?demo=1`은 잠원역 4번 출구 기준, 없으면 1회 GPS(실패 시 잠원역).
   - 르 파운드는 파일럿 경로로 연결, 나머지는 카카오 도보 딥링크로 안내.
1. **경로 미리보기**: 지도, 6단계, 입구 사진/층.
2. **출구 안내(ORIENTING)**: "출구를 등지고 서세요" + 사진 + 맞아요/반대예요.
   - 이동 12m 이상이면 GPS 변위로 앞/뒤를 판정(나침반 없이도 가능).
   - 나침반은 신뢰할 때만 보조 증거로 사용.
   - 15초 안에 확정되지 않으면 랜드마크 예/아니오 질문 1개.
3. **길안내(GUIDING)**: 다음 행동 한 줄, 남은 거리, TTS, 진동.
   - 회전 30m 전 예고, 10m 전 "지금 좌회전".
   - 25m 이상 이탈 시 OFF_ROUTE, 10m 안으로 복귀하면 재개.
4. **랜드마크 대화**: "앞에 GS25 보여" → 주변 POI 매칭 → 맞아요/다른 지점/없음.
   - 동명 지점이 2개 이상이면 구분 질문.
5. **입구 모드(ARRIVING)**: 25m 전 입구 사진·층·간판, 도착 확인.
6. **로그**: 이벤트/위치/질문/역방향/이탈을 기록하고 `#arrive-summary`에 요약.

## 깃발 화살표 모드 (`?mode=flags`)

AR·카메라 없이 **다음 이정표까지의 화살표 + 거리**만 보여주는 보조 모드입니다.
기본값은 연속 안내이고, 경로 미리보기의 **깃발 화살표** 버튼 또는 `?route=...&mode=flags`로 시작합니다.

- 경로 위 이정표에 `flags[]`(12개)를 미리 꽂아 둡니다. AI는 런타임에 필요 없습니다.
- 앱은 기존 `router.progress`의 `s`/`d`와 하나뿐인 GPS/나침반 watch를 **공유**합니다.
- 화살표는 현재 위치 → 다음 깃발 방위에서 폰 heading을 뺀 각도입니다.
- 반경(기본 20m, 입구 12m) 안에 2회 들어오면 다음 깃발로 자동 진행합니다.
  `turn`/`cross`는 `s ≥ atM + 8m`도 만족해야 하고, `entrance`는 **도착 확인 버튼**이 필요합니다.
  GPS가 나쁜데 입구가 확실하면 **6초 안에 두 번** 누르면 수동 도착으로 처리합니다.
- 나침반이 `absolute=false`면 10m 이상 이동한 방향을 기준으로 화살표를 유지하고 "나침반 없음" 배지를 띄웁니다.
- 25m 이상 이탈이 10초 지속되면 경고를 내고 **연속 안내로 전환**할 수 있습니다.
  경로로 복귀하면 배지가 자동으로 사라집니다. 이탈 중에는 `s` 기반 건너뛰기를 하지 않습니다.
- heading offset 학습은 v1에서 **로그만** 남기고 화살표에 적용하지 않습니다(양성 피드백 방지).
- 건물 반대편을 가리키지 않도록 `validateFlags`가 폴리라인 8m 이탈·90m 초과 간격을 검사합니다.
- 지하/실내에서는 동작하지 않습니다. 지상 출구부터 시작합니다.

### 무음 큐 카드 (기본)

- 음성은 **기본 OFF**. 상단 "소리" 버튼으로 전역 토글합니다.
  깃발 모드에서는 켜도 `지금 회전`·`경로 이탈`·`도착`만 말합니다.
  연속 안내도 같은 설정을 따르며, 기본은 무음입니다.
- 평소에는 문장 대신 `동작 / 거리 / 이정표` 3줄, 큰 화살표, 거리 링, 진행 점으로 안내합니다.
- 진동: 다음 깃발 1회, 회전 임박 2회, 지금 회전 3회, 이탈 2회 길게, 도착 1회 길게.
- 회전 15m 전부터 회전 방향 가장자리가 맥동하고, `지금` 배지로 회전 시점을 표시합니다.
- 이탈 시 화살표는 **가장 가까운 경로점**을 가리키고 빨간색으로 바뀝니다.
- 폰을 주머니에 넣으면 방향은 알 수 없고, 사건(회전 임박/이탈/도착)만 진동으로 알 수 있습니다.
- 연속 안내의 **화면/큐**는 이번 범위 밖이지만, 음성은 같은 전역 설정을 따릅니다.

## 로그와 개인정보

- 기본 로그에는 **GPS 좌표를 저장하지 않습니다.** `fix` 이벤트는 정확도(`acc`)와 개수만 남깁니다.
- 필드 테스트에서 좌표가 필요하면 `?debug&logcoords=1`로 열거나, DEBUG 패널의 `좌표 기록` 버튼을 켭니다.
  이 설정은 **세션 한정**이며 localStorage에 저장되지 않습니다.
- 기존 로그는 DEBUG 패널의 `로그 삭제`로 지울 수 있고, 다운로드 JSON에도 기본적으로 좌표가 없습니다.

## 캐시/배포

- 앱 셸은 cache-first, `data/routes/*.json`은 **network-first**입니다. 같은 캐시 버전에서 경로 데이터만 바뀌어도 새로 받습니다.
- 배포할 때 `sw.js`의 `CACHE` 버전을 올립니다(현재 `guide-v8`).

## AI 도구 (MCP + skill)

독립 채팅 앱이 아니라 **OpenCode/Paseo의 AI가 호출하는 도구**입니다.

- MCP 서버: `guide/mcp/server.mjs` (stdio, 의존성 없음)
- 등록: `~/.config/opencode/opencode.json` → `mcp.nav`
- 스킬: `~/.config/opencode/skills/navigation/SKILL.md`
- 테스트: `node mcp/test.mjs`

도구:

| 도구 | 역할 |
|---|---|
| `nav_location` | 위치 사용 가능 여부. PC 도구라 폰 GPS는 직접 못 읽음 → AI가 역/동네를 물어봄 |
| `nav_search_places` | 주변 카페/맛집 후보(거리·도보 시간) |
| `nav_place` | 장소 상세 |
| `nav_route` | 도보 경로. 르 파운드는 6단계 + 깃발 12개 + 연속/깃발 딥링크 |
| `nav_open_guide` | 가이드 앱 링크. `mode: continuous`(기본) / `flags` |

예: OpenCode에서 "잠원역 근처 카페 추천하고 르 파운드로 안내해줘"라고 하면
AI가 `nav_search_places` → `nav_route` → `nav_open_guide`를 호출하고,
마지막에 받은 링크로 가이드 앱을 엽니다. **연속 길안내는 앱이 담당**합니다.

> MCP 도구는 OpenCode 데스크톱/Paseo를 재시작해야 로드될 수 있습니다.

## 데이터 (중요)

- `data/routes/jamwon4-le-four.json`은 **초안**입니다. `verified: false`.
- 채팅 데모 POI(`js/chat.js`)는 잠원 주변 OSM 카페/식당 초안입니다. 평점·영업시간은 없습니다. 카카오 Local API 키를 연결하면 실제 정보로 교체합니다.
- 출구/입구 사진은 **임시 SVG placeholder**입니다. 현장 사진으로 교체해야 합니다.
- 랜드마크(나이스가이, 본죽, 디오연세치과, 취향, 카페쁄라, 르 파운드)는 OSM 주변 POI 기반 초안입니다.
- 출구가 바라보는 방향(`facingDeg`)과 입구/층/간판은 **현장 확인**이 필요합니다.
- 확인 후 `verified.method`를 `manual`로 바꾸고 사진을 교체하세요.
